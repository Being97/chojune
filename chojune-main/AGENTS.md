# 공통 작업 지침

## 응답과 작업 범위
- 기본 응답 언어는 한국어로 한다.
- 변경 전에 관련 코드, 프로젝트 설정, 문서를 확인하고 기존 구조와 스타일을 따른다.
- 요청을 해결하는 데 필요한 범위만 수정하고, 요청과 무관한 리팩터링이나 의존성 변경은 하지 않는다.
- 사용자가 작성한 기존 변경 사항을 임의로 덮어쓰거나 되돌리지 않는다.
- 요구사항이 불명확하고 코드나 문서로 확인할 수 없는 경우에만 필요한 내용을 질문한다.

## 보안
- 환경 변수 값, 비밀키, 토큰, 인증 정보는 응답이나 로그에 출력하지 않고 커밋하지 않는다.
- 환경 변수 설명에는 실제 값 대신 변수 이름과 용도만 기록한다.

## 반복 작업 가이드
- 반복 작업의 상세 절차는 워크스페이스 루트의 `.zoo/guides/` 아래에 작업 유형별 문서로 관리한다. 이 프로젝트 루트 기준 상대 경로는 `../../.zoo/guides/`이다.
- 작업을 시작할 때 해당 유형의 가이드가 있으면 먼저 읽고 적용한다.
- 초준 웹의 로컬 접속이나 배포 주소를 확인할 때는 `../../.zoo/guides/chojune_web_접속.md`를 먼저 읽는다.
- 가이드에는 확인할 파일, 작업 순서, 주의사항, 검증 방법, 완료 보고 항목을 기록한다.
- 공통 원칙은 이 문서에 유지하고, 작업별 상세 절차를 중복해서 적지 않는다.
- 가이드가 없는 작업에서는 기존 코드와 관련 문서를 기준으로 진행하며, 요청 없이 가이드를 새로 만들지는 않는다.

## 임시 실행 파일과 작업 종료 후 정리
- 작업 실행이나 일회성 검증을 위해 만든 임시 스크립트, 실행 파일, 로그, 스크린샷, 브라우저 임시 프로필은 작업 종료 후 안전하게 삭제한다.
- 임시 산출물은 기존 파일과 구분되는 전용 임시 위치에 만들고, 이번 작업에서 직접 생성한 경로를 기록한다.
- 삭제 전 생성 경로와 소유 범위를 확인하고, 이번 작업에서 만든 임시 산출물만 정확한 경로로 삭제한다. 출처가 불명확하거나 사용자가 수정한 파일은 임의로 삭제하지 않는다.
- 정리 과정에서 기존 코드, 사용자 파일, 기존 변경 사항, 프로젝트 설정이나 의존성을 수정하거나 되돌리지 않는다. 광범위한 파일 삭제나 저장소 초기화로 정리하지 않는다.
- 브라우저 검사 등 임시 실행에 필요한 도구는 기존 설치를 우선 활용하고, 일회성 실행만을 위해 프로젝트 코드나 의존성 설정을 변경하지 않는다.
- 이번 작업에서 직접 시작한 임시 프로세스만 종료하며, 사용자가 실행한 개발 서버나 기존 브라우저 세션은 종료하지 않는다.
- 요청한 기능의 구현 파일과 지속적으로 사용할 회귀 테스트는 임시 실행 파일과 구분하여 보존한다.
- 임시 산출물 삭제에 실패했거나 보존이 필요한 경우, 남은 경로와 이유를 완료 보고에 명시한다.

## 검증과 완료 보고
- 변경 후 프로젝트에 정의된 명령을 확인하고, 변경 범위에 맞는 린트, 타입 검사, 테스트 또는 빌드를 가능한 범위에서 수행한다.
- 검증 실패 시 이번 변경으로 발생한 문제와 기존 문제를 구분해서 보고한다.
- 실행하지 못한 검증은 수행한 것처럼 표현하지 않고, 미실행 사실과 이유를 명시한다.
- 완료 보고에는 변경 내용, 검증 결과, 남은 주의사항을 간결하게 정리한다.
